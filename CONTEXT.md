# Not A Wrapper

Domain language for the multi-AI chat app: one chat surface, many model providers, with tools layered on top of every conversation.

## Language

### Backend

**Convex module**:
The single server-side Convex source tree at `convex/`, including schema, functions, migrations, generated bindings, and Convex-domain tests. UI and component folders may import the root module's generated API, but must not contain copied Convex source trees.
_Avoid_: server copy, UI Convex mirror, `components/ui/convex`

**Authenticated handler**:
A Convex `query`/`mutation` defined through an auth-injecting builder (`authenticatedQuery`, `ownedChatMutation`, `ownedProjectMutation`, `ownedMcpServerMutation`, `ownedGenerationRunMutation`, …) instead of calling `ctx.auth.getUserIdentity()` inline. The builder resolves the caller's user — and, for owned-resource variants, fetches and ownership-checks the resource — before the handler body runs, injecting `ctx.user` (and `ctx.chat`/`ctx.project`/…) and enforcing one error contract (Not authenticated → not found → Not authorized). It makes auth structural, not a call you must remember. Ownership may be transitive: `ownedGenerationRunMutation` keys on a `runId`, fetches the **Generation run**, and resolves the owner through `run.chatId` (via the shared `requireOwnedGenerationRun`), injecting `ctx.run`/`ctx.chat`/`ctx.user`; since ADR-0021 its ONLY registration is `stopGenerationRun` (the sole user-token run write — it carries no usage input). Every other run-scoped write (`markGenerationRun*`, `updateAssistantSnapshot`, `createToolApprovalRequest`, `recordToolInvocations`) is registered ONLY as a grant-authorized internal mutation on the **Durable worker wire**; all of them keep auth-free `...ForChat` logic cores that take the injected `AuthenticatedRunOwner`, so a client-supplied `chatId` cross-check (`run.chatId !== args.chatId`) is structurally unrepresentable rather than hand-written. `prepareGeneration` is on `ownedChatMutation` because it creates the run (the admission proof is verified against the injected `ctx.chat.publicId`); `approveToolCall`/`denyToolCall` are on `ownedToolApprovalMutation`, which keys on the public `approvalId` and resolves ownership transitively through approval → run → chat (via `requireOwnedToolApproval`, injecting `ctx.approval`/`ctx.run`/`ctx.chat`/`ctx.user`). Internal functions and the HTTP chat-route token path stay outside the seam; public-only reads (share links) and anonymous/optional-auth paths use their own non-throwing builders. Self-identity-match handlers (`identity.subject === arg`) are a distinct shape, not an owned-resource one.
_Avoid_: auth helper (the older bypassable `convex/lib/auth.ts` form), middleware, guard

**Convex seam test**:
A backend test that calls a registered Convex function the way the client does — through `convex-test` against the real `api.*` / `internal.*` reference, with `t.withIdentity` for the caller — so the **Authenticated handler** builders, the argument validators, and the index semantics are on the test surface (ADR-0034). Files are `*.seam.test.ts` with a per-file `@vitest-environment edge-runtime` pragma and load the module table from `convex/test.setup.ts`. Reserved for security-critical registrations and index-range invariants; what a `...ForChat` core does once admitted stays in the core-level tests, which keep their hand-rolled `ctx` fakes and consolidate only when a file is already being edited.
_Avoid_: integration test (too broad), end-to-end test (no HTTP or browser is involved), migrating every fake to `convex-test` for its own sake

### Client

**Per-user subscription**:
The single client seam — a `usePerUserQuery` hook — every per-user Convex live read goes through. It owns the one correct subscribe gate, `isConvexAuthenticated` (the Convex JWT is synced), not WorkOS session presence (`!!user` / `!!userId`), and returns `"skip"` until it is true, so a signed-out or mid-auth-sync caller never opens a subscription or executes a wrong-empty read against a not-yet-resolved identity. It is the client counterpart to the **Authenticated handler**: the subscribe gate becomes structural instead of an `isAuthenticated ? {} : "skip"` ternary each call site re-derives with a different predicate (and which `userKeys.getProviderStatus` forgot entirely). A lint rule bans raw `useQuery` from `convex/react`; there is currently no public/share-link live client read, so any future one must introduce a named seam with a real caller. The hook returns auth-readiness alongside the data so providers stop re-deriving `data === undefined && authState` loading logic by hand. Since ADR-0031 the seam's `useQuery` is the convex-helpers cached variant: an unmounted query's subscription is parked for a bounded idle TTL (`lib/convex/query-cache.tsx`), and `useWarmPerUserQuery` opens one ahead of its consumer — the **Warm query cache**.
_Avoid_: skip gate, auth ternary, guarded query

**Warm query cache**:
The convex-helpers query cache mounted at the Convex client boundary (ADR-0031) with a bounded idle TTL and idle-entry cap, so a revisited chat renders its delivered selected-conversation pair on the first commit instead of a loading state. Warming (`useWarmSelectedConversation`, wired to sidebar row hover and click) is a momentary start/end through the cache registry — the same state a consumer leaves on unmount — never a second delivery path: values still flow through the one `ConvexReactClient`, so the ADR-0027 same-transition guarantee holds. It is in-memory only; nothing survives a reload.
_Avoid_: preloadQuery (the server seam), local-first store, persisted cache

**Client directive**:
The `"use client"` banner, governed by ADR-0019: in `components/ui/` it appears if and only if the file itself has client behavior — hooks (including library hook chains like Base UI's `useRender`), in-file event handlers or refs, or browser globals. Forwarding caller props and composing primitives from libraries that ship their own banner are not behavior. Styling primitives with callable helpers (cva exports) and pure display components stay shared so server components can use them; design tokens stay in CSS variables (never React context) to keep that possible. Product components under `app/components/` may keep an intent-documenting directive even when hook-free. This deliberately exceeds upstream shadcn, whose remaining banners are issue-driven inertia — never "fix" a missing directive by matching their files. RSC boundary enforcement is `bun run build:next`, not dev mode or `tsc`.
_Avoid_: use-client-by-default, client component (for the file-level banner decision — a shared file can still render in client trees), matching upstream banners

### Chat

**Chat turn**:
One user action that changes a conversation and may produce an assistant response: a new message, a regeneration, or an edit. Edit and regeneration are server-owned variants — the backend creates a message branch and derives the new selected path — and may target any prior message, so they require a durable (authenticated, server-persisted) chat. Guest/local chats are send-only.
_Avoid_: submission, send flow, message lifecycle

**Chat turn runtime**:
The request-scoped server module that executes one **Chat turn**. `prepare()`
consumes the route-admitted provider credential, resolves the model, adapts
history, prepares tools, and asks the
**Durable turn runtime** to enforce concurrency and create the generation run
before any model call. `toResponse(signal)` owns `streamText`, response shaping,
abort telemetry (through the **Stream liveness tracker**), and both stream-completion callbacks in one closure; durable
snapshot, approval, and terminal-write policy remain in the **Durable turn
runtime**. The route is the HTTP adapter and owns the one provider-credential
resolution between usage check and increment; the runtime reuses that same
server-only provider/key/source fact for model, tool, error, and telemetry
consumers without reading user-key storage again. The implementation uses
the standalone `toUIMessageStream({ stream: result.stream, ... })` converter,
while `createUIMessageStreamResponse(...)` retains ownership of the HTTP
envelope. See `docs/adr/0006-chat-turn-runtime.md`.
_Avoid_: chat handler, stream pipeline, request orchestrator (too vague); session (collides with the client `ChatSessionProvider` and the WorkOS auth session); Tool runtime (that is the composed sub-module, not this)

**Durable turn runtime**:
The second internal seam the **Chat turn runtime** composes (beside the **Tool runtime**) — the deep module (`app/api/chat/durable-turn-runtime.ts`) behind which ALL durable knowledge for one **Chat turn** lives: durable-prepare (the `prepareGeneration` call with the **Approval continuation**'s responses, latest-user-message selection, the argument-validation→400 mapping, history canonicalization, and **Execution grant** minting), and the one-shot AI SDK lifecycle binding `bind(toolFacts)` grouping the rest by AI SDK position — `streamTextExtras` (approval gating + the approval-persistence transform), `stream.*` (throttled snapshots, per-step tool-invocation upserts, failure marks, abort flush, the `captureFinish` half of the finish handoff — a missed handoff is LOUD: `durable_finish_handoff_missed` warn + Sentry before the `countToolParts` fallback), and `envelope.*` (identity answers; `settle(outcome)` owning the settle-approvals/observed-step-writes → flush → **final full-parts snapshot** → bounded-retry terminal ordering and resolving a typed **Settlement receipt** — `confirmed | degraded | guest` — that NEVER rejects, so a persistence failure cannot fail the response pipe or erase a delivered answer). `fail(err)` stays legal at any phase. Two production adapters behind one selecting factory that internalizes `isDurableConvexChat` — the Convex adapter and the inert guest adapter — so the caller never asks "is this turn durable". The user token plus the server's signed proof authorize admission ONLY; every post-prepare write travels the **Durable worker wire** (grant-authorized Convex HTTP endpoint `/chat-turn/worker`), which is also the test seam (`deps.workerWire`). Consumes the Tool runtime through the `ToolFacts` port (`source`/`approvalFor`/`toolApproval`, structural, test-fakeable); AI SDK shapes cross unwrapped. Callback return types describe SDK backpressure: void step writes are still retained and drained before local terminal settlement; double-terminal writes are not deduped client-side — the **Generation run lifecycle**'s first-terminal-wins absorbs them. Composed INSIDE `toResponse()`'s single closure — both onEnd layers still share it (ADR-0006 intact); the module names the handoff, it does not split it. See `docs/adr/0009-durable-turn-runtime.md` and `docs/adr/0011-durable-turn-settlement.md` (which supersedes ADR-0009's captured-token worker writes, rejecting finalize, and post-prepare `fetchMutation` wire).
_Avoid_: session (banned collision); durable runtime (the old `durable-runtime.ts` helper file — vocabulary, not a module); persistence layer / store (it owns a timeline with ordering invariants, not passive storage); recorder (undersells the identity answers); finalize (the pre-ADR-0011 rejecting terminal write — the verb is now settle)
_Status_: implemented 2026-07-05; deepened to settlement (grant + binding + receipt) 2026-07-18 (ADR-0011).

**Execution grant**:
The run-scoped worker credential (ADR-0011) that separates user admission from server execution in a durable **Chat turn**. Minted per turn by the **Durable turn runtime**'s Convex adapter: a 32-byte random secret whose SHA-256 digest rides the `prepareGeneration` admission call and is stored on the **Generation run** row (`grantDigest`, `grantExpiresAt`); the raw secret lives only in the Next server process's memory. Worker writes present it as `Authorization: Bearer` to the Convex HTTP action `/chat-turn/worker` (`convex/http.ts`), which hashes it BEFORE dispatch (pure-TS `sha256Hex`) so the secret never enters a mutation argument or log; the grant-authorized internal mutations (`convex/chatRuntimeWorker.ts`, `requireGrantAuthorizedRun`) verify digest, expiry, and exact run→chat→user linkage transactionally, then call the shared `...ForChat` handlers. Since ADR-0021 the grant wire is the ONLY authenticator for post-prepare run writes — the former user-token twins were deregistered because `markGenerationRunCompleted.usage` became the authoritative allowance-settlement input, and a user-token twin would have let a chat owner settle their own platform reservation at a self-declared cost (only `stopGenerationRun`, which carries no usage input, stays user-token; the boundary is pinned in `convex/chatRuntime.test.ts`). A mid-run user-token expiry therefore cannot reject a worker write (the 2026-07-14 incident class). Revocation = expiry + the terminal status guards (writes to a settled run are idempotent no-ops).
_Avoid_: worker token / service token (it is not a bearer identity, it is a per-run capability); admin key (explicitly rejected — minimum authority for one run); grant (unqualified — collides with tool approvals)

**Approval continuation**:
The trailing assistant message's live approval responses (`app/api/chat/approval-continuation.ts`): the one module that decides whether a request continues a paused tool approval and what the responses are. Only the trailing assistant can continue; historical responses are persisted evidence. A responded part is well-formed only with an approval id and decision (the AI SDK's own contract); anything else is rejected as a 400 before either runtime reads it, so the **Chat turn runtime** (the 409 gate, then the history/tail split validated for provider, registry, and execution-kind continuity) and the **Durable turn runtime** (response persistence at durable-prepare) can never classify one request differently. The split runs at two boundaries on purpose: on the wire messages before durable-prepare mutates approval state, and on the server-canonical history it returns.
_Avoid_: approval resume, pending-tool replay, a second responded-part predicate anywhere, lenient state-only matching
_Status_: implemented 2026-09-04 (one predicate; extraction moved out of the Durable turn runtime).

**Chat turn controller**:
The client-side counterpart of the **Chat turn runtime** — the single React-free module (`lib/chat-turn/`, entry `chat-turn-controller.ts`) that executes one client **Chat turn** behind one adapters seam. It owns turn validation (length, generation-active, durable-only gates for edit/regeneration), optimistic frames and their rollback, the async run sequence (auth → limits → chat creation → uploads → dispatch), plan building (edit trim, regeneration target — `turn-plans.ts`), **Chat turn wire contract** body assembly, and guest/local persistence routing (`turn-store.ts`, composed INSIDE `createChatTurnController` — the parent hook supplies store adapters and never builds or holds the store). Runners read the **Turn context** snapshot at run time and see adapters live at call time, not construction time (callers may swap an adapter after constructing the controller). `use-chat-core.ts` is the React shell: it constructs the adapters from hook state and the AI SDK and calls the controller; `lib/chat-store/turns/` retains only the **Branch projection** (`selected-path.ts`).
_Avoid_: chat-turn-service (the old two-layer split: runners in `app/components/chat/chat-turn.ts`, builders in `lib/chat-store/turns/chat-turn-service.ts`), session (banned collision), parent-held turnStore (the store is internal), client chat turn runtime (runtime is the server module)
_Status_: implemented 2026-07-06.

**Detachable stream binding**:
The client ownership unit for one AI SDK Chat instance plus the origin identity its finish-time work routes to (`ChatStreamBinding` in `use-chat-core.ts`). The mounted hook owns exactly one attached binding; a mounted chat-id transition away from a chat (browser Back/Forward over the shallow-pushState first-turn flow) replaces it in the same render and marks the old binding **detached** — the in-place equivalent of the link-nav remount, so navigation never aborts a generation (Stop stays the only user-facing abort). A detached binding's stream keeps flowing to its own callbacks: business logic routes through the latest closures, but identity comes from the binding's frozen `ownerChatId` — a detached guest finish caches into its origin chat, a durable finish is a client no-op (settlement is server-owned, ADR-0011), and a detached binding refuses `sendAutomaticallyWhen` and surfaces no toasts. Every detached stream gets the same hard time budget the attached stuck-stream guard enforces (a watchdog `stop()`), bounding orphan lifetime and spend even when settlement degrades. A mounted transition **back to** a chat whose detached binding is still streaming **re-adopts** it (the inverse of detach, same layout commit): lifecycle returns to attached, the watchdog clears, and the surface resumes the word-granular local array instead of the 750 ms durable snapshots — Convex stays the recovery plane for reload/second-tab/other-device only. Liveness for re-adoption reads the SDK chat's `status`, never the lifecycle's `finished` flag (it latches after the first completed turn); a server-selected path that proves branch divergence rejects the obsolete binding and falls back to Convex, while an empty or merely lagging path does not block re-adoption. Durable run-scoped Stop targets the selected run after a remount or from another tab; same-tab return still prefers re-adopting the local binding. Heartbeats and the lease reaper bound stale projected state after worker loss. See `docs/adr/0013-back-navigation-detaches-the-stream.md`.
_Avoid_: instance epoch / keyed useChat id (the earlier same-day mechanism — it shared one latest-closure callback set across instances, which mis-routed detached finishes to current navigation state); abort-on-Back (the pre-0013 behavior this replaces); rendering foreground tokens through Convex at a faster snapshot cadence (couples paint to the durability plane against ADR-0016); keeping response components globally mounted
_Status_: implemented 2026-07-18 (ADR-0013); return re-adoption amendment 2026-07-28.

**Atomic first-turn creation**:
The one-transaction commit of a durable chat's existence: `chats.createWithFirstTurn` creates the chat row inside an optional owned project, binds the complete staged-attachment set (`files.bindStagedAttachmentsToChat`, the shared validate-all-before-any-patch core `attachStagedFiles` also delegates to), and persists the initial user message through the **Message branch writer** — so a failure rolls back everything and a durable chat cannot be created without its first user message. The generation run still starts via `POST /api/chat` afterwards (ADR-0009/0011 intact): `prepareGeneration`'s idempotent `writeUserMessage` claims the pre-persisted row by `clientMessageId` (the turn's optimistic id) and adopts the run's provenance stamp onto it (first-turn user-message writes are the one provenance-less branch write; the writer's provenance type is all-three-or-none). Client side, `ChatsProvider.createFirstTurnChat` owns the guest-local vs durable split (auth readiness gate and optimistic sidebar ops unchanged), `ensureChatExists` returns the `EnsuredTurnChat` shape and navigates only after the commit, and `runSendTurn` skips its own binding call and sends the **Selected path token** as the server fact — `{count: 1, tail: userMessageId}` — instead of deriving it from its still-empty rendered array. Retry is identity-preserving: the allocation retains the committed turn's `clientMessageId`/payload and re-presents it to a same-payload retry (even after the route prop catches up) so the dispatch claims the persisted row instead of duplicating it; acceptance (`confirmDispatched`) consumes the identity. Edits never allocate: the edit runner's durable-chat guard already proves the chat exists. See `docs/adr/0012-atomic-first-turn-creation.md`.
_Avoid_: create-then-attach, compensating deletion of zero-message chats (rejected — sweeping on inference is the bug class the terminal-stub rules exist to prevent), navigating before the commit
_Status_: implemented 2026-07-18.

**Generation run**:
The durable record of one model-generation attempt within a **Chat turn** — created at durable-prepare, linked to the assistant message it streams into, carrying status (`queued → running → streaming → awaiting_approval | completed | aborted | failed`), usage, finish reason, and tool counts. One turn normally owns one run; regenerations and approval continuations create a new run against existing messages (the continuation closes the paused run via the **Generation run lifecycle**'s approvals-resolved signal).
_Avoid_: generation (ambiguous with the model call), stream (that's the transport), job

**Generation run lifecycle**:
The single pure domain module (`convex/domain/generation_run_lifecycle.ts`) owning the legal transitions of a **Generation run** and its paired assistant message. Signal-shaped: `resolve(current facts, signal) → verdict`, where signals are `complete / fail / abort / supersede / approval-requested / approvals-resolved / stop / lease-expired / approval-expired / continuation-lost` and the verdict names the run patch plus the message resolution (stamp, keep **Terminal outcome stub**, delete-and-reselect sibling, restore-completed for a regeneration that died pre-snapshot). Owns the race rules in one table: first terminal outcome wins; failed may overwrite completed (the onError-vs-envelope race must converge to failed) but never aborted (user Stop is settled); completion downgrades to awaiting_approval while approvals pend; supersede reaches only queued/running/streaming (paused runs are closed by deny-pending at next-turn prepare, never swept); the reaper signals settle what nothing else reaches — lease-expired fails a dead worker's run, approval-expired an unattended pause, and continuation-lost a pause whose approvals all resolved but whose continuation never dispatched (denied → aborted, approved → failed; legal only from awaiting_approval, so no signal resurrects a settled run). Mutation handlers gather facts and apply patches; they do not re-derive legality.
_Avoid_: state machine helper, status guard, transition utils (all too vague — this is the one brain, not a helper)
_Status_: implemented 2026-07-05.

**Terminal outcome stub**:
An empty assistant message kept (not deleted) with a terminal status (`failed`/`aborted`) when a run dies before producing content and no semantic sibling exists to fall back to. It renders as an inline failed/stopped state with retry, projects into model history as an explicit "never answered" marker, and is counted symmetrically by client and server visibility (the **Selected path token**'s two-pass validation exists so a stub materialized by the supersede sweep never falsely rejects the turn that triggered it).
_Avoid_: empty placeholder (that's the pre-terminal state), ghost message, deleting failed turns (the bug this fixes)

**Message branch**:
A sibling message alternative under the same parent message, created by durable edits and regenerations so prior turns remain addressable instead of being overwritten or deleted.
_Avoid_: fork (too broad), version (too overloaded)

**Message branch writer**:
The single mutation-scoped Convex module that commits complete **Message branch** changes through three role-shaped operations: write an idempotent user message, write an assistant placeholder, or select an existing branch. It owns legacy normalization, effective-parent resolution, sibling selection, sparse-safe branch-index and message-order allocation, insertion, and post-write **Selected path** validation; callers retain ownership and optimistic-concurrency checks, approval and title policy, **Generation run** creation, and model-history projection.
_Avoid_: branch-write helpers (the shallow primitives it replaces), generic insert/select command (leaks user-message idempotency), message store (it owns branch invariants, not passive persistence)
_Status_: implemented 2026-07-11.

**Branch context**:
The canonical immutable snapshot (`createBranchContext` + `*FromContext` primitives in `convex/domain/message_branches.ts`) of one message-array version's branch facts — sorting, legacy effective parents, sibling grouping/order, lookup maps. All branch semantics live in the factory and primitives; production consumers unconditionally share one context per query/plan or planned array version. A context is valid only for the exact array it was built from and is never reused after a branch field changes. The array-based helper exports are convenience adapters, not a second algorithm. Semantic tests cover legacy linear chats, selected paths, sibling metadata, normalization, malformed trees, and branch writes directly.
_Avoid_: branch cache (it is rebuilt per version, never invalidated in place), second branch implementation (the adapters delegate and tests assert semantics directly)
_Status_: implemented 2026-07-22; rollout lever and redundant shadow query removed after soak on 2026-07-23.

**Chat-owned deletion**:
The mutation-scoped Convex module that atomically removes a Chat's complete durable graph — messages, **Generation runs**, assistant message snapshots, tool invocations, tool approval requests, tool-call log rows, and attachments plus stored files — through role-shaped `deleteChat(chat)` and `deleteChatsForProject(project)` operations. The first updates surviving Project activity; the second removes every Project Chat graph without updating or deleting the Project, leaving **Authenticated handlers** to own authorization and root deletion; leaf-first/root-last ordering, storage-failure rollback, and bounded preflight make late writes converge while oversized Project deletion fails without committing.
_Avoid_: cascade delete (generic and implicit), deletion helpers (the shallow primitives it replaces), cleanup (undersells complete ownership), async deletion job (not the current atomic policy)
_Status_: implemented 2026-07-18.

**Selected path**:
The backend-derived linear path through a chat's message branches used for rendering and model history. Hidden sibling branches stay stored but are not sent to the model until selected.
_Avoid_: visible messages, active transcript

**Branch projection**:
The single client seam that installs the backend's selected path into the AI SDK's flat `useChat` array while a chat is idle: it adopts server ids and branch state onto matching live messages, preserves in-flight optimistic sends, and swaps wholesale when the path diverged (a branch switch, or restoring messages a rejected edit/regeneration sliced out). It is the sole owner of client identity adoption — matching by message identity across the full selected path (not a positional tail patch) and reading server ids through one typed accessor (`readServerMessageId` in `lib/chat-messages/branch.ts`). The client renders the server's selected path; it does not re-derive it. See `docs/adr/0001-client-renders-server-selected-path.md`.
_Avoid_: reconcile (too narrow — that's only the id-adoption half), rehydrate, sync

**Message metadata module**:
The single client module (`lib/chat-messages/metadata.ts`) that owns message `metadata`: one private set of server-owned keys, the `isRecord` guard, and the typed readers/writers (`getServerMessageId`, `getBranch`, `stampServerFields`, `adoptServerOwned`) every caller goes through instead of casting `metadata as Record<string, unknown>` and hand-poking keys. The durable adapter and the branch projection call its writers; renderers call its readers. The streamed assistant-metadata blob is projected through a named validator (`vToolInvocationStreamMetadata`, `convex/lib/messageMetadata.ts`) at the persist boundary so only the owned key-set is written and malformed writes are rejected; the storage column (`messages.metadata`) is narrowed to that same validator so the stored shape is provably the owned key-set, not an opaque `v.any()`. Branch stays a transient, droppable descriptor; the writers preserve reference identity on no-op (the projection's idempotence contract) and pass client-transient keys (e.g. `reasoningDurationMs`) through untouched.
_Avoid_: metadata bag, ad-hoc cast, `metadata as Record`

**Selected path token**:
The forward (client→server) staleness guard for a chat turn — a `{ expectedVisibleMessageCount, tailMessageId? }` descriptor the client derives from the rendered selected path and sends with a new-message turn; the backend validates it before mutating and rejects a turn raced against a changed selected path. It is the counterpart to the branch projection (the backward, server→client half) and is unrelated to it despite the shared name; edits and regenerations carry their own count guard (`expectedChatVersion`) instead of the token.
_Avoid_: conflating with branch projection (that's the backward half), version (overloaded)

**Chat turn wire contract**:
The single statement of the `POST /api/chat` request shape (`lib/chat-messages/chat-turn-contract.ts`), imported by both sides of the HTTP seam: the client turn builders produce `ChatTurnBodyFields` (the AI SDK transport merges in `messages`), and the chat route validates the result through `parseChatTurnRequest` — required fields, edit⊕regeneration exclusivity, and the guest-id rule — before constructing the **Chat turn runtime**'s input. One declaration, so a field added or renamed on one side is a compile error on the other. The contract is closed (no extras spread or index-signature escape hatch — a new wire field is added here first) and carries the trust taxonomy in one place: caller identity is session-derived server-side (ADR-0010), `userId` is read only as the guest rate-limit key, and `isAuthenticated` deliberately does not exist on the wire. Edit and regeneration cross as `ChatTurnEditRequest` / `ChatTurnRegenerationRequest` — the same names on both sides; the **Selected path token** crosses spread flat into the body fields.
_Avoid_: per-side request types (`ChatRequest` vs `ChatTurnRequestBody`, the pre-contract duplication), intent-vs-request split naming (`ChatTurnEditIntent`), `bodyExtras` / body index signature (the escape hatch this closes), sending `isAuthenticated` in the body (identity is never body-derived)
_Status_: implemented 2026-07-06.

**Chat list window**:
The bounded, recency-ordered slice of a user's chats the **sidebar** subscribes to — a `usePaginatedQuery` of all **non-pinned** chats over `by_user_pinned_updated` (`getRecentWindowForCurrentUser`), plus a small live pinned read over the same membership-preserving index. This is the sole sidebar path after the default-on rollback lever's 2026-07-23 soak. Project membership stays in the window so the sidebar owner can derive either grouping without N+1 project subscriptions: **In one list** interleaves project and non-project chats, while **By project** filters project chats from global Chats and uses the same recent rows as project previews. It is deliberately NOT the full chat list: a chat write invalidates only the window, not the whole `by_user` collection. The client `useChats()` store narrows to this window; the id-keyed optimistic overlay applies to it, so an op on a chat outside the window is a no-op in the sidebar (the surface that shows that chat reflects it via its own read). `isLoading` from the store means "first window page ready," not "all chats loaded." Per-chat access outside the window goes through `useChat(chatId)` (a targeted `chats.getById` fallback), and `chats.updatedAt` is the single activity field the window orders by — one bump per durable turn, at turn start.
_Avoid_: the full chat list, `getForCurrentUser` as the sidebar source (that is the pre-ADR-0005 unbounded read), recent chats (ambiguous)

**Sidebar status projection**:
The run-scoped, owner-only mirror that lets every subscribed **Chat list window** row derive its trailing status from the Chat document it already renders. A run claims `statusRunId` and writes `liveRunStatus`; only that run may later update or clear the projection, so a late terminal event cannot clobber a newer run. Completion and failure also stamp `lastRunEndedAt`/`lastRunStatus`, while `lastReadAt` controls unread/error presentation. `liveRunFreshUntil` is a once-written ceiling—run budget at prepare, approval expiry while paused—so stale backend state cannot animate forever. Public and non-owner reads strip every projection field. The initiating tab may supply an immediate non-idle override while Convex catches up, but an idle local transport never lowers a fresh backend projection.
_Avoid_: a separate sidebar-status query or hydrator, unguarded terminal projection, exposing owner status fields on shared reads, treating the local ready state as proof that a durable run settled
_Status_: implemented; freshness and terminal behavior are governed by the **Generation run lifecycle** and **Generation presentation resolver**.

**Sidebar row system**:

**Turn evidence**:

**Provider stream smoothing**:
An evidence-gated server transformation for a specific provider whose decoded text deltas arrive in bursts too large for frame-level presentation. It is not a global presentation policy: naturally fine-grained provider output passes through unchanged, and the client never decomposes canonical text into a word-reveal queue.
_Avoid_: global smoothing, client smoothing, word-by-word mode

**Streaming Markdown projection**:
The interpretation of canonical assistant text as stable completed blocks plus a context-verified mutable tail. Stable blocks retain their identity while the tail grows; ambiguous Markdown may widen or invalidate the tail, and correctness falls back to the full existing Markdown interpretation rather than changing parser semantics.
_Avoid_: streaming parser (the parser is unchanged), permanently frozen blocks, parser swap

**Growing code presentation**:
The streaming state of an unfinished or recently changing fenced code block. Its canonical code appears immediately without syntax highlighting; highlighting begins only after a short idle boundary or terminal settlement, and conversations without code never initialize the highlighter.
_Avoid_: token-frequency highlighting, eager highlighter startup, withheld code

**Stream metadata**:
The sparse semantic events that accompany a foreground assistant stream: its start, meaningful metadata changes, and terminal settlement. Ordinary text and reasoning deltas do not emit empty metadata records.
_Avoid_: per-delta metadata, empty metadata, metadata heartbeat

**Foreground stream authority**:
The active tab's local AI SDK message state, fed by the direct HTTP response or an authenticated replay of the same generation run (ADR-0039). It alone drives foreground token presentation; Convex records run status, periodic durable snapshots, and terminal state. A refreshed document restores saved text immediately, reconstructs retained history silently, then follows live chunks at their arrival cadence. Reconnection can begin before client subscription hydration through the same owner-checked route; unavailable replay leaves checkpoint recovery active.
_Avoid_: Convex-driven foreground streaming, dual foreground authority, snapshot-as-token-state

**Retained generation stream**:
The short-lived ordered Redis log of one execution's structured UI chunks and immutable starting assistant state. Its identity is the generation run, including a new run for each approval continuation. It supports replay followed by live reads without starting generation; ownership, selected path, Stop and settlement remain in Convex. Reader disconnection never cancels the producer. Refresh restores saved text immediately, reconstructs retained history silently, then presents new live output; old text is never animated from the beginning.
_Avoid_: second run lifecycle, snapshot smoothing, worker-crash continuation guarantee

**Foreground notification cadence**:
The maximum one-browser-frame window in which the active AI SDK message state may coalesce notifications before React presents the latest canonical text. It is a client state-notification boundary, not a second presentation queue; the browser may still combine multiple mutations into one painted frame.
_Avoid_: reveal cadence, token timer, direct DOM cadence, paint guarantee

**Terminal stream flush**:
The ordering boundary for complete, Stop, error, approval pause, retry replacement, and navigation detachment. Any pending canonical text becomes observable before terminal metadata or status settles, after which final Markdown and code presentation may complete without changing the canonical response.
_Avoid_: terminal drain (implies a reveal queue), delayed trailing text, settle-before-flush

### Tools

**Tool runtime**:
Everything a chat request needs to use tools, prepared once per request and alive for the whole stream: the merged tool set, per-tool metadata, step gating, budget accounting, and tool outcome recording.
_Avoid_: tool coordinator, tool orchestrator, tool loader

**MCP connection**:
The module shared by the Tool runtime and the settings connection test that owns URL validation, DNS-pinned transport creation, discovery, cancellation, and cleanup under one preparation deadline per server (ADR-0035). It returns tools and an idempotent close operation; successful chat connections stay alive until the Tool runtime disposes them.
_Avoid_: raw SDK client ownership in callers, separate connection and discovery deadlines

**Tool layer**:
One of the sources tools come from — Layer 1 (provider-native), Layer 2 (Exa search/content fallback), Layer 3 (user-configured MCP servers). Layers are merged into the tool runtime; later layers win name collisions.
_Avoid_: tool source (reserved for the per-tool metadata field), tier

**Capability policy**:
The per-request decision of which tool capabilities (search, extract, mcp, code) a user/model/key combination may use, and which specific tools are allowed in early vs late steps. Search receives the resolved route-level `searchMode`: `optional` permits native or Exa tool injection when enabled, `always-on` relies on inherent provider grounding without injection, and `unsupported` rejects enabled search. The generic `tools` matrix owns every other capability axis.
_Avoid_: permissions, feature flags

**Tool budget**:
The per-tool call allowance enforced during a request — probed before provider-executed calls, consumed after execution, degrading to a request-local soft cap when the policy store is unreachable.
_Avoid_: rate limit, quota

**Tool outcome**:
One record per tool call — tool identity and display name, source, success, duration, error, budget fields, input/output previews, token usage — assembled by the tool runtime when the call's step finishes and pushed through outcome sinks injected at preparation (audit log, analytics, trace log). Every call produces an outcome, including failures and tools the runtime cannot identify; errors are recorded for all sources. The runtime accumulates outcomes and exposes a request-level summary.
_Avoid_: tool call log entry (that's one sink's projection), tool trace (reserved for the in-flight timing/error data the outcome consumes), tool result (reserved for the provider's result payload)

### Models

**Vendor**:
The open-set presentation identity of a model's maker — an icon plus display name (`claude`, `gemini`, `grok`, `deepseek`, `meta`, `qwen`, …) — distinct from **Provider**, the closed key-bearing API surface that has a **Provider strategy**. The catalog's `icon` and `baseProviderId` fields point into vendor space, not provider space; wrapped OpenRouter models carry real vendor ids without registered icons and fall back to the OpenRouter icon. Known vendors live in the **Provider identity** module's vendor registry; icons live in a client-only sibling registry keyed by the same vendor ids so server code never imports React components.
_Avoid_: brand (rejected — clashes with `baseProviderId` naming already in the catalog), provider (reserved for the key-bearing surface), conflating the two in one list (the pre-unification `PROVIDERS` array mixed both vocabularies untyped)

**Logical model**:
The user-facing model identity (ADR-0020) — what the selector shows once and every preference and persisted document (`chats.model`, `messages.model`, `generationRuns.model`, favorites, last-used) speaks in. Compiled in `lib/models/catalog.ts` from route records: each unmapped `ModelConfig` becomes a logical model whose id EQUALS its canonical route id (direct route when one exists, else the sole wrapped route), and its canonical route supplies the authoritative full `name` plus optional explicit `shortName`; mapped routes never override presentation. Wrapped records join a direct model only through the explicit `logicalModelId` mapping authored in the OpenRouter allowlist. Compilation throws on any ambiguity (missing target, chained mapping, duplicate route, two same-provider routes on one model). `resolveModelSelection` is the one compatibility layer from any historical id (alias → succession → merged route id) to logical identity plus an optional `legacyRouteHint`.
_Avoid_: fuzzy display-name dedup, a hand-maintained second catalog (routes stay the authoring inputs), UI-only dedup (`.filter()` in the selector), treating `:free` pool entries as routes of their paid siblings (distinct serving tier, deliberately separate models)

**Model route**:
A concrete execution path to an upstream provider — the existing `ModelConfig` record IS the route record, its id the stable route id; `ModelRoute` wraps it with `{modelId, providerId, upstreamModelId, config}`. Route-specific facts (capabilities, pricing, context, reasoning construction, `searchMode`) stay on the route. The client view (`LogicalModelView`) aggregates search as optional when any route honors the toggle, otherwise always-on when any route is inherently grounded, otherwise unsupported; the **Route resolver** filters both enabled and disabled requests so the selected route preserves that behavior.
_Avoid_: route-shaped selector entries (the pre-ADR-0020 duplicate rows), reading `providerId` off a logical model as if it named THE execution provider

**Route resolver**:
The one server-owned decision (`lib/model-route-resolver.ts`, consumed by `validateAndResolveChatCredential`) of how a chat turn reaches its logical model: candidates are the model's routes filtered by required capabilities (vision and effective web-search state) and the approval-continuation provider pin, ordered priority-BYOK → **Platform entitlement** → fallback-BYOK, with the legacy route hint promoted inside its tier and direct-provider-before-aggregator as the deterministic tie-break; each candidate is walked against the ACTUAL server credential (BYOK decryption, platform env var), so client key-status booleans and stale ciphertexts can never admit a turn. Returns an immutable receipt (`modelId`, `routeId`, `providerId`, `upstreamModelId`, `credentialSource`, `routeReason`) whose trusted admission tuple is HMAC-signed by the Next.js server and verified by Convex before the **Generation run** is created; the assistant message keeps `model` (logical) + `provider` for replay. Credential/route precedence BEFORE provider execution only — never runtime failover (no retrying provider failures on another route without an explicit retryable-error taxonomy and idempotency proof).
_Avoid_: deriving a provider from the selected model id at the route boundary, client-authoritative route choice, runtime fallback-on-error, re-routing an approval continuation (Convex's `approval_provider_mismatch` stays the fail-closed enforcement)

**Platform entitlement**:
The typed seam (`lib/models/platform-entitlement.ts`) answering "may this route run on platform-funded credentials for this actor?" — the RULES half of platform admission: `FREE_MODELS_IDS` for authenticated platform use, `NON_AUTH_ALLOWED_MODELS` for anonymous. Since ADR-0021 entitlement alone no longer admits an authenticated platform candidate — the **Platform usage allowance** reservation must also land (the balance half). It also decides where the API-key **preference** control (`userKeys.preference`, `"priority" | "fallback"`, absent = priority — the historical BYOK-first behavior) is meaningful: only providers serving a model that also has a platform path show the Priority/Fallback toggle; elsewhere key settings explain the key is used for every applicable request.
_Avoid_: account balances or usage counters in the catalog/selector, `accessible` as a server-trusted fact (it is presentation; admission re-derives), treating list membership as economic admission (that is the reservation's job)

**Platform usage allowance**:
The included platform-spend budget (ADR-0021): one materialized `usageBuckets` balance per user per UTC-month plan period, every change evidenced by an append-only `usageLedgerEntries` row, with `usageReservations` linking each platform-funded request to its run. 1 credit = 1 micro-USD; all amounts are integers, rates compile from catalog numeric pricing into a per-reservation **pricing snapshot** (settlement always prices with the snapshot, never the live catalog; unpriced routes fail platform funding closed). The route resolver's platform tier reserves atomically (`usageAllowance.reserveAuthorized`, idempotent on `(userId, requestId)`, fingerprint-conflict-checked) BEFORE a platform candidate may win; the reservation attaches to the run inside `prepareGeneration` (its id rides the signed admission proof) and settles inside the SAME Convex mutation as every terminal lifecycle transition, under the provider-boundary rule: release before provider work structurally began, settle actual/observed/estimated usage after — overruns record negative balances, never clamp. EXCEPT cancellation (ADR-0021 amendment 2026-08-28): a user Stop or supersession terminalizes the run immediately but keeps the reservation held and accounting-PENDING for a bounded evidence window; the stopped worker's settlement-only `finalizeTerminalUsage` receipt (authenticated against a settlement digest copied onto the reservation, not the revoked run grant) or the 15s deadline reconciler then settles from evidence via the shared pure decision (`resolveTerminalUsageSettlement`): actual aggregate, completed-step usage, or estimated input plus a bounded partial-output estimate (bases: `actual`, `actual_with_estimated_title`, `observed_partial`, `estimated_input_floor`, `estimated_input_with_partial_output`; `estimated_after_unknown_usage` is legacy-read-only for new cancellations; the title component settles independently via `titleSettlementBasis`). Title generation is metered at the title route's own rates; per-step usage accumulates on the run as abort/reaper evidence; a cursor-bounded reconciler cron is the final net. BYOK turns never touch allowance; anonymous turns stay on the subsidized guest path (no wallet); daily message counters remain abuse limits only (the pro-model counters are retired). The settings General tab shows used/pending percentages and the refill date.
_Avoid_: check-then-debit balance flows (the TOCTOU race the reservation removes), floating-point dollar accounting, clamping an overrun to zero, charging from the `priceUnit` string, a second best-effort onFinish billing pipeline (settlement rides the durable lifecycle), a second cancellation billing tree (receipt, deadline reconciler, lease-expiry, and worker aborts all go through `resolveTerminalUsageSettlement`), cash-like anonymous wallets, purchasing/Stripe (explicitly out of scope)

**Generation output budget**:
The per-turn total generation allowance (ADR-0028), centralized in `lib/openproviders/output-budget.ts`. Auto BYOK omits the provider limit; an explicit user budget applies to either credential source. Platform funding independently adds an 8,192-token response ceiling and reserves the route-aware worst case before execution. Hidden reasoning shares the total allowance: fixed Anthropic thinking is subtracted before the generic AI SDK value because that adapter adds it back, while OpenAI/Google reasoning consumes the provider limit directly. Because AI SDK limits each model call separately, the Chat turn runtime subtracts every completed step's output usage before the next call and stops when the turn allowance is exhausted or usage is unknown. Requested and applied values ride the request, signed admission proof, durable run, and assistant metadata so retries and approval continuations preserve the same policy. OpenRouter max-output affordability errors remain terminal and offer a user-initiated 16K retry; the app never parses the provider's human-readable affordable-token count or retries automatically.
_Avoid_: a universal BYOK cap, a second output default inside usage estimation, credential-source branches at the `streamText` call, parsing provider prose as a numeric contract, automatic paid retries

**Provider identity**:
The single server-safe module (`lib/provider-identity.ts`) owning what is identically true about a key-bearing provider everywhere it appears: the `Provider` and `ToolProvider` id unions (and their `KeyedProvider` union — both kinds share the encrypted `userKeys` storage), each provider's company display name (key-settings tiles use the company identity — Anthropic, Google, xAI — never the product brand; model rows keep **Vendor** identity), the provider→vendor link, the key-setup facts (placeholder, get-key URL, mask hint; for tool providers also description, cost estimate, and env-var name), and the known-vendor registry. Icons are the one client-only sibling (`lib/provider-icons.tsx`), keyed by vendor id. Deliberately excludes the **Provider strategy**'s static SDK facts — the model-provider env-var name stays on the strategy; identity is what the UI and key storage agree on, not how an SDK is constructed. The ADR-0007 snapshot generator derives each model's `provider` display name from this module and validates `providerId`/vendor ids at generation time, so a provider that exists in the runtime union but is missing from key settings (or vice versa) is a failing inventory test, not a shipped inconsistency.
_Avoid_: three parallel provider lists (`lib/providers` + the two key-panel arrays — the drift this replaces), aliasing one provider to its product brand in key settings (the old anthropic→"Claude" tile), `Provider.id: string` (the untyped conflation), re-homing `envVarName` for model providers (strategy-owned)
_Status_: implemented 2026-07-11.

**Provider strategy**:
The single home for everything statically true about one model provider's AI SDK: how to instantiate its client (a BYOK key vs the provider's default/env credentials), its optional native built-in search tool plus that tool's display metadata, and its platform API-key environment-variable name. Stateless; one per provider, selected from the already-resolved `ModelConfig.providerId` (`lib/openproviders/provider-strategy.ts`). Model construction consumes that concrete route directly; there is no second model-id-to-provider router after admission. The same instance backs both the language model and the search tool, so tool calls structurally bill to the same key as the model — the BYOK billing invariant is structural. `languageModel` is synchronous (the registry is statically constructed; provider SDKs are eagerly imported, and every provider now returns the AI SDK 7 `LanguageModelV4` contract). It deliberately excludes anything that is not a static SDK fact: route admission (the **Route resolver** already owns it), key selection/precedence (BYOK > env, decryption — it only declares the env-var name; `getEffectiveProviderApiKey` consumes it), request shaping (per-model request policy — stays a free function), and history adaptation (a sibling seam with a different, non-1:1 taxonomy). OpenRouter is the documented irregular — configured factory key selection, `.chat()`, `openrouter:` prefix strip, construction-time reasoning settings, and an automatic server-side web-search tool — with every divergence body-internal so the shared interface never widens.
_Avoid_: provider wrapper, provider factory (too narrow — that is only `languageModel`), provider adapter (reserved — the history-replay adapters are a different seam)

**History adaptation**:
The single target-provider seam that turns canonical `UIMessage[]` history into replay-safe history before `convertToModelMessages`. The **Chat turn runtime** first separates a valid approval continuation and lowers historical provider-hosted activity to provider-neutral text, then `adaptHistoryForProvider` selects exactly one adapter for OpenAI, Anthropic, Google, OpenAI-compatible, text-only, or default behavior. The adapter owns provider-linked metadata stripping, final tool-pair preservation, role repair, and provider-specific replay shapes; model-bound validation then fails closed before a request reaches the provider. The OpenAI adapter keeps a text part's `phase` (read through Turn evidence) while stripping every server-linked id, so replay stays self-contained and follows OpenAI's guidance to resend `phase` on assistant messages (ADR-0041). The adapter interface and final provider-request matrix are the test surface.
_Avoid_: a second normalize→compile→adapter pipeline, rollout flags for an incomplete provider matrix, compiler-to-adapter fallback telemetry
_Status_: single seam adopted 2026-08-30; see ADR-0029.

**Request shaping**:
Everything provider-specific about issuing one model request, resolved from the model config plus request context (active search tools, tool presence): provider options such as thinking/reasoning configuration, per-model thinking budgets, and provider beta headers. Owns provider-workaround invariants (e.g. SDK pause_turn downgrades) so callers never branch on provider. Reasoning visibility is requested explicitly, never assumed from the provider default (ADR-0041): Anthropic adaptive requests carry `display: "summarized"` (4.7+ defaults to `omitted`; never sent on the fixed-budget path) and Mistral reasoning routes send `reasoningEffort: "high"`. A route may claim `reasoningText: true` only when the installed adapter can deliver reasoning parts; `inlineReasoningTags` marks routes whose reasoning arrives as literal tags for the **Chat turn runtime** to lift at the stream seam. Stays a free function keyed by `providerId`, deliberately outside the **Provider strategy**: its variation is per-model and per-request (the reasoning-text gate, the search-active thinking downgrade, the token-efficient header), not a static provider fact.
_Avoid_: provider options (reserved for the AI SDK field it produces), model tuning, trusting a provider's default reasoning visibility

### Observability

**Run timing receipt**:
The durable, content-free record stamped on a **Generation run** at settlement of where that run's time went: server preparation, the provider's time to first output, the server's delay before first response write, model response time, tool execution, the wire stream window, and settlement. Every worker terminal write (completed, failed, aborted) carries it, recording only the segments that write observed (absent means unobserved, never zero-filled), so runs compare by model, route, and build; browser-side time (network delivery, render, paint) is outside it and belongs to **Chat-performance instrumentation**. A user Stop or supersession terminalizes the run before the worker's own abort write can carry the receipt, so that transaction copies the revoked grant's digest into a single-use, bounded **receipt-attach capability** on the run (`timingReceiptGrantDigest`); the stopped worker's `attachRunTimingReceipt` then lands its partial receipt against that copy and can patch no other run field; the payload is a partial `RunTimingReceipt` (optional `*Ms` segments plus `buildId`, sanitized before persistence), and only the single-use attach capability mirrors ADR-0021's settlement-only authorization pattern. A reaped run mints the same capability, but its worker is presumed dead, so reaped runs usually carry none; `timingSummary` ranges over completed runs only and reports its receipt-bearing count beside the run count.
_Avoid_: perf metrics / telemetry (unqualified), spans (those are the sampled log seam), latency breakdown, timing metadata (the message-level **Generation stats** is a different, user-facing record)
_Status_: implemented 2026-09-01 (ADR-0030); read via `runTiming:timingSummary`.

**Stream liveness tracker**:
The request-local tracker (`app/api/chat/stream-liveness-tracker.ts`) beside the reasoning-activity, work-duration, and generation-timing trackers: it owns which phase a streamed turn is in, the post-tool stall timer, and the rule that no diagnostic signal fires after completion or an execution abort and a stall fires at most once. Fed by the **Chat turn runtime**'s stream callbacks, it hands back a content-free snapshot; the runtime adds identity tags and captures it to Sentry. Timing anchors stay with the generation-timing tracker (ADR-0030).
_Avoid_: stall detector (undersells the phase and abort ordering), telemetry state in closure lets, timing (that is the **Run timing receipt**'s source)
_Status_: implemented 2026-09-04.

**Generation stats**:
The user-facing record on an assistant message of how its generation performed: time to first output (any output chunk, reasoning included; persisted as `timeToFirstTokenMs`), the output stream window, and the provider-reported input, cached-input, output, and reasoning token counts, accumulated across an approval continuation. It holds only figures comparable across models, so nothing about this server's own overhead. Tokens per second is derived at presentation and never stored: VISIBLE (non-reasoning) output tokens over the output stream window, because providers that hide reasoning generate it before the first output chunk — inside time to first output, outside the window — and counting it would inflate the rate by exactly the hidden share. Provider-run (hosted) tool calls execute inside the provider response, so their time stays inside the window; they are counted so the line can say so. Absent provider usage stays absent rather than estimated. Shares its provider figures with the **Run timing receipt**.
_Avoid_: stats for nerds (a borrowed product name), usage (the billing aggregate), response stats, token metrics
_Status_: implemented 2026-09-01 (ADR-0030); behind the `showGenerationStats` preference, off by default.

**Chat-performance instrumentation**:
The content-free, off-by-default measurement seam for chat responsiveness (`lib/observability/chat-performance.ts` core + `chat-performance-client.ts` React hooks + the callback-ref-owned **Composer paint probe**). Client turn/navigation/composer-paint marks go to the User Timing API behind the build-time `NEXT_PUBLIC_CHAT_PERF_INSTRUMENTATION` flag; server preparation spans and checkpoint counters emit `_tag:"chat_perf"` structured log lines behind per-request `CHAT_PERF_SAMPLE_RATE` sampling. Every event passes a per-event field allow-list (unknown fields — string fields especially — are rejected; strings must be declared enums or the correlation id, and credential-shaped values are refused). A per-turn random UUID crosses as the one-shot `x-chat-perf-id` header, is validated by the route, rides only spans, is never persisted to any document, never reused across turns, and is never an admission idempotency key. The measurement protocol lives in `docs/performance/measurement-runbook.md`.
_Avoid_: analytics (PostHog product analytics is a different sink and identity domain), tracing (Sentry spans exist independently; this seam owns only the plan's content-free performance events), live toggle (every NEXT_PUBLIC_ flag is a redeploy)
_Status_: implemented 2026-07-22; default off everywhere.

**Composer paint probe**:
The content-free controller (`lib/observability/composer-paint.ts`) attached to the stable ProseMirror editing DOM. It classifies eligible `keydown`/`beforeinput` pairs, marks editor paint after one animation frame and settled Composer paint after two, drops timestamps older than one second, and cancels frames/listeners with the editor callback-ref lifecycle. It emits no draft text, selection, key value, or input type, and returns a shared no-op controller while Chat-performance instrumentation is disabled.
_Avoid_: per-keystroke React state, prompt content in performance entries, always-on listeners while instrumentation is off, effect-owned editor timing
_Status_: implemented 2026-08-23.
