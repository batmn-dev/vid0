# 41. Provider reasoning, commentary, and answer lifecycle at the API boundary

- Status: implemented
- Date: 2026-09-09
- Preserves: ADR-0016 immediate rendering, ADR-0026 reasoning effort, ADR-0029 single history seam, ADR-0039 replay, ADR-0040 inline work

## Context

Every route shares one UI lifecycle, one inline-work renderer, one persistence path, and one replay path, but providers expose reasoning and answer phases differently. Three defects followed from leaving provider defaults alone: Anthropic 4.7+ models default `thinking.display` to `omitted`, so Opus 4.8, Sonnet 5, and Fable 5 streamed empty thinking blocks and the UI showed an opaque "Thinking" timer with no narrative; Mistral routes claimed reasoning text but never sent the only enabling value (`reasoning_effort: "high"`); and OpenAI history replay dropped the documented `phase` label along with the server-linked item ids. Two further gaps were structural: the OpenAI-only `phase` read was spelled in three modules, and the pre-answer duration (`workSummaryDurationMs`) froze only on an OpenAI `final_answer` boundary, so unphased tool turns lost "Worked for Ns" on reload.

## Decision

Reasoning visibility is requested explicitly per provider in Request shaping, never assumed from the provider default: Anthropic adaptive requests carry `display: "summarized"` whenever the catalog says reasoning is visible (a no-op on 4.6 where it is already the default; never sent with the fixed-budget `enabled` path), and Mistral reasoning routes send `reasoningEffort: "high"`. A catalog route may only claim `reasoningText: true` when the installed adapter can actually deliver reasoning parts: `mistral-medium-3-5` is flagged false because the installed adapter's id gate never forwards the option for that id, and Perplexity `sonar-reasoning-pro` stays false because the API's default streaming mode suppresses reasoning events and the adapter has no field for the separate ones.

Text phase and reasoning visibility have exactly one reader each, in Turn evidence: `readTextPhase` (the only place a provider namespace such as `providerMetadata.openai.phase` is spelled) and `readReasoningVisibility` (`visible` when trimmed text is non-empty, otherwise `opaque`: Anthropic omitted/redacted, OpenRouter encrypted, empty OpenAI summaries). The client projection, the server work-summary tracker, the replay prefix guard, and the OpenAI history adapter all call these readers. Unphased text keeps the ADR-0040 rule: a block is commentary if and only if a tool call appears later in part order; sources, reasoning, and implied-search items never make text commentary.

Pre-answer duration is provider-neutral and end-time. `workSummaryDurationMs` freezes at the recorded `text-start` of the first explicit `final_answer` block; otherwise, once the stream ends, at the recorded `text-start` of the first non-empty text part that began after the turn's last tool activity, or, for turns without tool calls, after provider-supplied sources (implied search, the Perplexity shape); otherwise it stays absent. Sources never reset a candidate, the same way they never make text commentary. The tentative value is never published mid-stream, so a later tool call cannot leave a wrong number in a checkpoint. The chat-turn runtime observes stream parts in exactly one callback (the streamText `onChunk`, which precedes the UI-stream conversion for every part) and resolves the rule on the `finish`, `abort`, or `error` chunk, so the final durable snapshot and the `finish` message metadata carry the same number. A Stop after answer onset keeps its value. The user's Stop is a Convex mutation that makes the run terminal before the worker can write anything more, so the worker cannot resolve the rule for it; instead every checkpoint carries rule 2's tentative onset under a private `workSummaryCandidateMs` key the UI never reads (cleared with an explicit null when a later tool call makes that text commentary), and the shared lifecycle terminal (`applyLifecycleVerdict`, which Stop, supersession, and failure all reach) promotes it to `workSummaryDurationMs` because the part order is complete at that point; completion replaces the metadata blob, dropping the key. Server-originated aborts (provider deadline, lease loss) are the worker's own terminal: the streamText `onAbort` resolves the rule and hands the number to the durable binding, whose flush inside `onAbort` writes it even when text and parts are unchanged (the snapshot tracker treats the number as a content-version change). Provider failures take the same path: the `error` chunk resolves the rule, and `noteStreamError` notes the value and flushes the tracker before `markGenerationRunFailed`, so a failure that lands between throttled checkpoints neither loses the number nor lets the verdict promote a candidate that a later tool call had already cleared.

Inline reasoning tags are lifted at the server stream seam. A catalog route may declare `inlineReasoningTags: "think"`; the runtime then composes an abort-aware transform before word chunking and the lifecycle transform that turns a literal `<think>…</think>` section into ordinary `reasoning-start/delta/end` parts, withholds `text-start` until the first answer character, splits a text part when reasoning opens after answer text so part order matches reading order, holds back at most a partial tag, closes an unterminated section at `text-end`/`finish`, and forwards the SDK's `abort` terminal after cancellation (it is enqueued upstream of every `experimental_transform`; swallowing it would hide `isAborted` from the UI-stream conversion and the durable settlement). The durable tracker, Redis, and the browser therefore see the same canonical parts and persisted `content` never carries tag text. No shipped route declares the flag: Perplexity `sonar-reasoning-pro` was the candidate, but its default streaming mode never emits the tags, and lifting every literal `<think>` section out of ordinary answer text would silently remove content a user asked the model to write. The flag stays available for a route that demonstrably streams tagged reasoning.

The client's live work clock (the "Worked for Ns" estimate before the server value lands) anchors to the assistant message's arrival, the stream's `start` chunk, rather than to its first renderable part. The server clock starts immediately before provider consumption, which is the same instant the `start` chunk leaves; anchoring later made a Low-effort Anthropic search turn read "Worked for 2s" live and "Worked for 4s" settled. Measured after the change: 3 s live, 3415 ms persisted, 3 s settled.

OpenAI history replay keeps `phase` on text parts while still stripping every server-linked id (`itemId`, annotations) and every reasoning-part metadata, so replay stays self-contained and never serializes `item_reference` lookups.

## Alternatives

- Client-side `<think>` parsing: rejected; it would create a second text interpretation and could not fix persisted `content`.
- Per-provider renderers or a wire-level `phase` stamped in message metadata: rejected; part-level truth already rides the SDK stream and survives its own replay reconstruction.
- LLM-generated activity labels (LibreChat's `generatePhase`): rejected as fabricated progress; every live label stays application-derived and model text appears only as commentary narrative.
- Treating text between tools as answer until settlement: rejected; pre-tool narration would enter the final answer.
- Publishing the tool-order duration candidate mid-stream as the value: rejected; a later tool call would persist a wrong number. It is persisted only under a private candidate key that the UI never reads and that the next checkpoint clears, so only a terminal transition ever promotes it.

## Consequences

- Anthropic 4.7+ direct routes stream reasoning text again at every effort level (verified live on Opus 4.8 at High and Low).
- Unphased tool turns show the same "Worked for Ns" live, after a hard refresh, and after completion (verified live on Opus 4.8 with web search: live 4 s, persisted 4622 ms).
- OpenRouter still cannot surface reasoning that arrives after content within a step (the installed provider accumulates it without emitting); the route resolver's preference for direct routes remains the mitigation.
- Anthropic `pause_turn` is still not continued; incidence on 4.7+/5 could not be measured in this pass (PostHog access unavailable).
- The `@ai-sdk/anthropic` enum rejects `display: "updates"`, so Fable 5 progress updates remain indistinguishable from reasoning under `summarized`; an SDK upgrade is the prerequisite for a real commentary channel.
- `grep -rn "openai?.phase"` outside `lib/chat-messages/turn-evidence.ts` returns nothing in production code; adding a phase source is one edit.
- The tool-order duration resolves at stream end, so an unphased turn refreshed between answer onset and finish shows "Worked" without a number until finish metadata lands, and a client reloaded before onset restarts its live clock at reload; the settled value is always the server's. Seeding the row clock from the run's `workStartedAt` is the follow-up.
- The inline-work paint snapshots (ADR-0040) are released on a frame-bound schedule. Visible Anthropic reasoning made a long stream capture a full narrative clone per text update, and a hidden document never released them (measured: 101 clones, 1.2 MB of text, renderer unresponsive). The narrative now skips capture while `document.hidden`, releases retained clones on `visibilitychange`, and caps retention at six clones when frames stall while visible.
